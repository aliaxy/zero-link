# AGENTS.md

This file is the canonical development guide for AI coding agents working in this repository.

## Project State

zero-link is currently in a skeleton-only stage.

The repository intentionally has:

- No generated go-zero service code.
- No handwritten API or RPC service implementation.
- No API route contracts.
- No protobuf RPC methods.
- No business database schema.
- No short-link business logic.

Do not add any of the above unless the user explicitly asks for that implementation stage.

## Repository Layout

- `docs/`: product, architecture, engineering, workflow, and planning documents.
- `deploy/`: deployment and local infrastructure assets. Local Docker Compose files belong here.
- `etc/`: reserved local configuration files for future services.
- `services/link-api/`: reserved for the future go-zero HTTP API service.
- `services/link-rpc/`: reserved for the future go-zero RPC service.
- `migrations/`: reserved for future database migrations.
- `web/admin/`: reserved for the future embedded admin UI.

## Development Rules

- Preserve the skeleton-only boundary unless the user explicitly asks for implementation.
- Do not run `goctl` generation unless the user explicitly asks for generated go-zero services.
- Do not handwrite code that should be generated by go-zero.
- Do not add API contracts, protobuf files, or migration SQL during the skeleton stage unless requested.
- Keep documentation in English.
- Prefer documentation-first changes when project intent or architecture changes.
- Keep changes small and scoped.

## Go And go-zero Rules

- The Go module path is `github.com/aliaxy/zero-link`.
- If the module ever needs to be recreated, use `go mod init`; do not handwrite `go.mod`.
- Future service names are `link-api` and `link-rpc`.
- Future go-zero services should use generated `ServiceContext` wiring.
- Do not introduce a dependency injection framework unless explicitly requested.
- Keep Docker Compose application service integration for a later stage; local infra is separate.

## Local Infrastructure

Use:

```bash
make infra-up
make infra-down
```

The local infrastructure Compose file is:

```text
deploy/docker-compose.infra.yml
```

This file should provide local dependencies only. Do not add application services to it unless requested.

## Verification

Run:

```bash
make test
```

Validate the Compose configuration with:

```bash
docker compose -f deploy/docker-compose.infra.yml config --quiet
```

The current skeleton has no Go packages, so `make test` should report that the skeleton foundation is ready.


```text
chore(deploy): add local infra compose file
```
