# AGENTS.md

This file is the canonical development guide for AI coding agents working in this repository.

## Project State

zero-link has completed Stage 8 (cache optimization and data lifecycle). Stages 1–8 are complete.

The repository intentionally has:

- Generated go-zero API and RPC services.
- API route contracts for health, readiness, administrator authentication, short-link management, redirect, and analytics.
- RPC methods for readiness, administrator authentication, short-link management, short-link resolution, visit recording, and stats query.
- Stage 3 foundation schema and generated MySQL models for administrator and short-link storage.
- Stage 5 analytics schema and generated MySQL models for visit events and daily stats (gozero naming style).
- JWT-based administrator authentication.
- MySQL-backed short-link create, list, detail, update, and soft-delete management logic.
- Redis-backed short-link resolution via goctl cached model (`FindOneByCode` with two-level index cache).
- `GET /{code}` redirect route returning 302/404/403/410.
- `AnalyticsMiddleware` that fires a non-blocking `RecordVisit` RPC goroutine on every 302 redirect.
- Vue 3 + Vite + Element Plus admin SPA under `web/admin/` with login, link management, and analytics views.
- CORS middleware in `link-api` configurable via `Cors.AllowOrigins` in service YAML.
- `GET /admin/links/{id}/stats` returning daily PV/UV within a date range.
- Local httpyac smoke request assets under `tests/httpyac/`.
- `MaxConns: 1000` and `MaxBytes: 1048576` connection protection on `link-api`.
- IP rate limiting on `GET /{code}` (20 req/s per IP) and `POST /admin/login` (10 req/min per IP) via go-zero `PeriodLimit` backed by Redis.
- `pkg/httputil.ExtractClientIP` shared utility in `services/link-api/pkg/httputil/`.
- Structured logging in `link-api` (login, auth middleware, redirect) and `link-rpc` (resolve, authenticate, analytics) using `logx.Infow` / `logx.Errorw`.
- Prometheus `/metrics` endpoints: `link-api` on port 9100, `link-rpc` on port 9101.
- Business metric counters `zerolink_redirect_requests_total{result}` and `zerolink_analytics_events_total{result}` in `services/link-rpc/internal/metrics/`.
- Unit tests for `AnalyticsMiddleware`, `IPRateLimitMiddleware`, and `LoginRateLimitMiddleware` using interface stubs and `goleak`.
- Reserved short codes extended to include `metrics` and `static`.
- Full-stack integration tests under `tests/integration/` covering the complete HTTP → link-api → link-rpc → MySQL/Redis chain, guarded by `//go:build integration` and run via `make test-e2e`.
- In-process cuckoo filter in `services/link-rpc/pkg/filter/` for cache penetration defence; loaded from `short_link` on startup and updated via Redis Pub/Sub channel `zl:code:created`.
- `ResolveShortLink` filter fast path: definitive miss returns `NotFound` without touching Redis or DB.
- Data retention cleanup runner in `services/link-rpc/internal/cleanup/` purging `visit_event` after 90 days, archiving soft-deleted `short_link` rows after 365 days, and pruning `link_daily_stat` after 730 days.
- `short_link_archive` and `reserved_code` tables under `migrations/000003_data_retention`; `reserved_code` model generated by goctl.
- `CreateShortLink` checks `reserved_code` for custom codes to prevent reuse of archived short codes.
- Prometheus counters `zerolink_filter_requests_total{result}` and `zerolink_cleanup_deleted_rows_total{table}`.

Do not add management UI, additional business contracts, or new stages unless the user
explicitly asks for that implementation stage.

## Repository Layout

- `docs/`: product, architecture, engineering, workflow, and planning documents.
- `deploy/`: deployment and local infrastructure assets. Local Docker Compose files belong here.
- `etc/`: root-level example and local configuration files.
- `services/link-api/`: go-zero HTTP API service.
- `services/link-rpc/`: go-zero RPC service.
- `migrations/`: versioned SQL migrations. Stage 3 includes the initial administrator and short-link schema. Stage 5 adds visit event and daily stat tables. Stage 8 adds `short_link_archive` and `reserved_code` tables.
- `tests/httpyac/`: local HTTP smoke requests and example httpyac variables.
- `tests/integration/`: full-stack integration tests (`//go:build integration`). Services are started as OS subprocesses by `TestMain`.
- `web/admin/`: Vue 3 + Vite + Element Plus admin SPA. Source under `src/`, build output under `dist/` (ignored by Git).

## Configuration Rules

- Every committed configuration file should have an example variant.
- Use `.env.example` for committed environment variable documentation.
- Use `.env.local` for machine-local environment values. Do not commit it.

- Use `etc/<service>-local.yaml` for machine-local service configuration. Do not commit it.
- Keep secrets and machine-specific values in ignored local files only.

## Go And go-zero Rules

- The Go module path is `github.com/aliaxy/zero-link`.
- If the module ever needs to be recreated, use `go mod init`; do not handwrite `go.mod`.
- Future service names are `link-api` and `link-rpc`.
- Future go-zero services should use generated `ServiceContext` wiring.
- RPC generation must be run from the repository root with:

```bash
goctl rpc protoc services/link-rpc/proto/link/v1/link.proto \
  --go_out=services/link-rpc/pb \
  --go_opt=paths=source_relative \
  --go-grpc_out=services/link-rpc/pb \
  --go-grpc_opt=paths=source_relative \
  --zrpc_out=services/link-rpc \
  --proto_path=services/link-rpc/proto \
  -m
```

- The `-m` flag enables service grouping: `link.proto` defines 4 services (`HealthService`, `AdminService`, `LinkService`, `AnalyticsService`), and goctl generates separate subdirectories under `internal/logic/`, `internal/server/`, and `client/` for each service.

- Proto files should use absolute `go_package` values without explicit Go package aliases, such as `github.com/aliaxy/zero-link/services/link-rpc/pb/linkv1`.
- Accept goctl-generated package names, client directories, and exported client identifiers as the source of truth.
- Do not introduce a dependency injection framework unless explicitly requested.
- Keep Docker Compose application service integration for a later stage; local infra is separate.
- Readiness checks may use simple dependency connectivity checks and must not depend on business data.

## Git Rules

- Do not make task changes directly on `main`.
- Create a task branch from `main` before implementation work.
- Choose branch prefixes by task type, such as `docs/`, `chore/`, `feat/`, `fix/`, or `ci/`.
- Example branch names:
  - `chore/config-example-local`
  - `docs/update-local-development`
  - `feat/link-redirect`
  - `fix/cache-invalidation`
  - `ci/add-github-actions`
- Before creating any commit, show the intended staged changes and commit message, then wait for explicit user confirmation.

Use Conventional Commits without emoji.

Format:

```text
<type>(<scope>): <subject>
```

Examples:

```text
docs: add agent development guide
chore(project): add service skeleton directories
chore(deploy): add local infra compose file
```

For the full workflow, see `docs/17-git-workflow.md`.
